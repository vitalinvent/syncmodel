# Ollama Model Transfer (Windows / Linux)

Утилита переносит выбранные модели Ollama между компьютерами, Windows, Linux и внешними дисками. Используются только стандартные библиотеки Python — ничего устанавливать через `pip` не нужно.

## Требования

- Python 3.10 или новее.
- На диске назначения должно хватать свободного места.
- Для импорта в системное хранилище Linux иногда нужны права `sudo` для смены владельца файлов.

## Запуск в Windows

Распакуйте файлы в одну папку и запустите `ollama_sync.cmd` двойным щелчком. Либо из PowerShell:

```powershell
py -3.10 .\ollama_sync.py
```

## Запуск в Linux

```bash
chmod +x ollama_sync.sh
./ollama_sync.sh
```

Либо напрямую:

```bash
python3 ollama_sync.py
```

## Работа через меню

1. **Экспорт** — выберите папку, где уже хранятся модели, нужные модели и каталог на флешке/диске.
2. **Импорт** — выберите каталог экспорта и локальное хранилище Ollama.
3. **Поиск** — покажет обнаруженные каталоги и список моделей.
4. При выборе нескольких моделей вводите номера через запятую (`1,3`) или диапазон (`1-3`). `0` означает все модели.

Папка экспорта — полноценный корень хранилища Ollama с каталогами `blobs` и `manifests`. На другом компьютере укажите эту папку как источник импорта.

## Проверка и безопасность

- Для каждого blob проверяется SHA-256 по digest из манифеста.
- Если файл назначения уже есть, он проверяется по SHA-256; повреждённый файл заменяется.
- Манифест записывается последним и только после успешного копирования всех blob-файлов модели.
- Неполные модели (с отсутствующими слоями или ошибочным манифестом) пропускаются.
- Источник и назначение не могут совпадать или быть вложенными друг в друга.
- Скрипт не удаляет файлы из источника и назначения.

Для наиболее надёжного переноса остановите Ollama на время копирования, особенно если в этот момент загружаются или удаляются модели. После импорта проверьте результат командой `ollama list`. При необходимости перезапустите службу.

## Где искать хранилище

Скрипт проверяет `OLLAMA_MODELS`, типовые пути Windows/Linux и распространённые точки монтирования внешних дисков. По FAQ Ollama стандартный путь в Windows — `%USERPROFILE%\.ollama\models`, а в Linux для стандартной установки — `/usr/share/ollama/.ollama/models`. В Linux путь также зависит от пользователя, от имени которого запущен сервер; пользовательский путь задаётся переменной `OLLAMA_MODELS`.

Если каталог не найден автоматически, выберите ручной ввод пути. Указывать нужно именно корень, внутри которого лежат `blobs` и `manifests`. При импорте в защищённый системный каталог Linux запустите программу с правами root, например `sudo python3 ollama_sync.py`.

## Импорт в стандартную Linux-службу

Если Ollama установлена как systemd-служба и работает от пользователя `ollama`, после импорта меню предложит выполнить `chown -R ollama:ollama`. Это действие требует root-прав и выполняется только после явного подтверждения. Его также можно выполнить отдельно:

```bash
sudo chown -R ollama:ollama /путь/к/хранилищу/models
```

## CLI (необязательно)

```bash
python3 ollama_sync.py list --dir /путь/к/models
python3 ollama_sync.py export qwen3:8b --from-dir /путь/к/models --to-dir /media/usb/ollama-export
python3 ollama_sync.py import qwen3:8b --from-dir /media/usb/ollama-export --to-dir /usr/share/ollama/.ollama/models
```

После импорта в Linux можно добавить `--fix-linux-permissions`, чтобы выполнить смену владельца:

```bash
sudo python3 ollama_sync.py import qwen3:8b --from-dir /media/usb/ollama-export --to-dir /usr/share/ollama/.ollama/models --fix-linux-permissions
```
